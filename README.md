# Телеканал: система управления сеткой вещания

Консольное приложение на Python для учёта и планирования эфирной сетки телеканала поверх базы данных MySQL. Позволяет вести справочники контента (фильмы, собственные и сторонние передачи, реклама, студии) и составлять из них расписание показов — как на конкретные даты, так и на регулярной основе (по дням недели).

## Возможности

- **Справочники контента** — полноценный CRUD (добавление, удаление, редактирование, просмотр списком) для:
  - фильмов, в том числе многосерийных (название + номер серии);
  - собственных передач телеканала, привязанных к студии съёмки;
  - сторонних передач;
  - рекламных роликов;
  - студий, на которых снимаются собственные передачи.
- **Программы вещания** — привязка сетки либо к дню недели (регулярное расписание), либо к конкретной календарной дате (с валидацией года/месяца/дня и високосных лет).
- **Показы (эфирные слоты)**:
  - ручное добавление показа с указанием времени начала и окончания;
  - автоматический поиск свободного окна в сетке заданной продолжительности и вставка показа туда;
  - удаление по точному времени, по интервалу пересечения, по программе, по конкретному фильму/передаче/рекламе;
  - редактирование — замена одного контента на другой в рамках показа;
  - гибкая выборка: по медиа-контенту, по временному интервалу, либо полный список с ограничением по числу строк.
- **Целостность данных** — при добавлении показа с ещё не существующим фильмом/передачей приложение предлагает сразу создать недостающую запись в справочнике (в том числе студию для собственной передачи).
- Понятный табличный вывод результатов в терминал (динамический расчёт ширины колонок, форматирование времени `timedelta` → `ЧЧ:ММ`).
- Весь пользовательский интерфейс — на русском языке, ввод короткими буквенными командами (`Доб`, `Удал`, `Изм`, `Вывод` и т. п.).

## Архитектура

Проект построен по слоям с чётким разделением ответственности:

```
main.py        точка входа — запускает бесконечный цикл интерфейса
interface.py    слой представления: меню, парсинг и валидация ввода пользователя
database.py     слой доступа к данным: классы-обёртки над таблицами MySQL, SQL-запросы
table.py        вспомогательные утилиты: форматирование времени и вывод таблиц в консоль
```

- `database.py` — класс `DataBase` инициализирует соединение с MySQL (`mysql-connector-python`) и создаёт по одному объекту-репозиторию на каждую таблицу (`ShowTable`, `StudioTable`, `FilmTable`, `OurTranslationTable`, `AdsTable`, `TranslationTable`, `ProgramTable`), унаследованному от общего `AbstractTable`.
- `interface.py` — зеркальная иерархия классов `*Interface` (по одному на сущность), каждый реализует меню действий и делегирует их в соответствующий репозиторий `database.py`. Класс `AppInterface` — корневой диспетчер, выбирающий нужный подынтерфейс по вводу пользователя.
- `table.py` — не зависит от БД, отвечает только за консольный вывод: построение ASCII-таблицы по списку колонок и данных, конвертация `timedelta` во время в формате `ЧЧ:ММ`.

## Схема данных

Логическая модель (восстановлена по запросам в `database.py`):

| Таблица | Ключевые поля | Назначение |
|---|---|---|
| `Program` | `dayName` / `date` | Программа вещания: либо день недели, либо конкретная дата |
| `Studio` | `address` | Студия съёмки |
| `OurTranslation` | `name`, `studioId` → `Studio` | Собственная передача телеканала |
| `Translation` | `name` | Сторонняя (покупная) передача |
| `Film` | `name`, `serie_num` | Фильм / серия |
| `Advertising` | `productName` | Рекламный ролик |
| `ShowTable` | `timeStart`, `timeFinish`, `programId`, + одна из `filmId` / `translationId` / `ourTranslationId` / `advertisingId` | Конкретный эфирный показ: время + программа + один вид контента |
| `fullshowsinfo` (представление) | — | Денормализованное представление для выборок показов со всеми связанными именами (используется в `select_*`) |

Показ (`ShowTable`) ссылается ровно на один тип контента одновременно — остальные внешние ключи выставляются в `NULL`.

## Технологии

- **Python 3**, без внешних фреймворков кроме драйвера БД
- **MySQL** — хранилище данных, доступ через `mysql-connector-python`
- Стандартная библиотека: `datetime`/`timedelta` — для работы со временем показов

## Запуск

```bash
pip install mysql-connector-python
python main.py
```

Перед запуском необходима развёрнутая MySQL-база с описанной выше схемой (включая представление `fullshowsinfo`) и параметрами подключения, заданными в `AppInterface.__init__` (`interface.py`).

## Возможные направления развития

- Вынести параметры подключения к БД (пользователь, база, пароль) в конфигурационный файл или переменные окружения вместо жёстко заданных значений в коде.
- Перейти на параметризованные запросы (prepared statements) вместо подстановки значений в SQL-строки через f-строки — повышает безопасность и устойчивость к некорректным вводимым данным.
- Добавить графический или веб-интерфейс поверх существующего слоя доступа к данным (`database.py` уже отделён от `interface.py`, что упрощает такую замену).
